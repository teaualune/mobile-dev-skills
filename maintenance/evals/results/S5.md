# S5 — submissions in `mobile-store-deploy`'s description

| | |
|---|---|
| State | 0.1.0-alpha.1: `mobile-store-deploy`'s description adds "For a review submission, names a plugin.", trimmed elsewhere to stay in the 2,100-character budget (2,100). No other description changed |
| Cases | `deploy-*` (5, with the new `deploy-submit-review`) and `neg-*` (7), 3 runs each |
| Run | 2026-11-18, Claude Code 2.1.327, `claude-sonnet-5-5`, `--ablation none`, `--threshold 0` |
| Deploy | 5/5 cases, every run passed `fired`; $1.25 |
| Negatives | 7/7 cases, every run passed `no-plugin-skill`, `neg-release-notes` ("Draft the What's New text …") included; $0.98 |

`deploy-submit-review` ("Build 2.4.0 (37) is on TestFlight now. Submit it for App Store review.") fired `mobile-store-deploy` in all three runs, so a submission request reaches its "Store submission" rule without a prior upload, while release copy alone still fires nothing. An earlier wording ("Asked to submit for review, names a tool.") gave the same results ($2.20).

**With `store-submission-prep` listed too** (its skill copied into a snapshot of the plugin for the run, not part of the suite; 3 runs each):
- the original description (before this state): no skill fired in any run, since `store-submission-prep`'s description takes a request to prepare a submission sheet, not one to submit ($0.13);
- this state's description: `mobile-store-deploy` fired in every run ($0.23); in two live runs with both plugins installed, it said it can't submit and offered the installed `store-submission-prep` ($0.20);
- a wording that deferred to a listed submission skill ("Review submission only if no skill for it is listed: names a plugin.") fired `mobile-store-deploy` all the same ($0.23 and two live runs, $0.20), so it wasn't kept.
