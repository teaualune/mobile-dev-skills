## Observations

- **One trigger miss, no misfires.** The only failed trigger is intake-requirements-dump run 2, where the prompt ends "What's still missing before we can build it?" and Claude answered that question directly instead of starting intake. The rest held:
  - positives: 44/45 runs fired;
  - no-other-plugin-skill: 27/27, so no positive case also fired a second plugin skill;
  - negatives: 21/21, no plugin skill called.
- **The sandbox blocks skills after they trigger (a suite limit, not a plugin behavior).**
  - With `allowed_tools: [Read, Glob, Grep, Skill]`, every Bash, Write or Edit call fails with "No such tool available".
  - In `dontAsk` mode, Glob on the plugin directory (outside the case cwd) is denied, while Read and Grep there work.
  - Most skill runs hit one of these. One scaffold run (scaffold-generate-files run 2) stopped without loading the adapter.

  This doesn't touch the trigger graders.
- **Fixture gaps that show up in the replies.**
  - deploy-upload-archive names `build/ios/archive/Runner.xcarchive`, but the fixture never creates it, and 2/3 runs reported it missing.
  - `scripts/build-version.sh` is a 4-line stub, and there is no `ios/` or `android/` folder. The deploy runs flagged both.
  - intake-new-feature asks for the reading-history feature, which already has an unfinished sheet in the fixture. 2/3 runs therefore took intake's resume path rather than a fresh intake. It still fires `feature-intake`, but if the trigger moves in a later state, this collision is a possible cause.
